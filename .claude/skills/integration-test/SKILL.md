# 통합 테스트 스킬 (A-SPICE SWE.5)

공통 위치와 ID 규칙은 프로젝트 루트 `CLAUDE.md`를 따른다. 테스트의 기준은 **소프트웨어 아키텍처**(컴포넌트, 인터페이스, 동적 거동)다. 단위 테스트가 모듈 내부를 본다면, 통합 테스트는 컴포넌트가 인터페이스로 맞물려 설계대로 동작하는지를 본다.

## 1. 필수 규칙

1. **함수 커버리지 100%, 테스트 성공률 100%를 달성할 때까지 테스트 케이스를 반복해서 추가한다.**
2. 필요하면 Stub/Mock을 쓸 수 있으나 **과도하게 의존하지 않는다.**
3. **커버리지 달성만을 위한 의미 없는 테스트 케이스를 추가하지 않는다.**
4. **모든 테스트 함수에 Doxygen 스타일 주석으로 테스트 목적, 입력값, 절차, 예상 출력값을 쓴다.**
5. **경계값 분석, 동치 클래스, PICT 조합을 적극 활용한다.**
6. **인터페이스를 중심으로 컴포넌트 간 연동 확인 위주로 시험한다.**

단위 테스트 스킬(`unit-test`)의 2절(케이스 도출), 3절(PICT), 4절(주석 형식), 5절(Stub/Mock)을 그대로 따른다. 이 스킬은 통합 수준에서 달라지는 점만 다룬다.

## 2. 합격 기준 (`CLAUDE.md` 2.1절)

- **함수 커버리지 100%** — LLVM(`llvm-cov`)으로 측정한다. 통합 시험 빌드에 `unit-test/scripts/coverage.sh --out build/cov-integration`을 사용한다 (MC/DC 옵션은 필요 없다).
- **테스트 성공률 100%** (실패·건너뜀 테스트가 없어야 한다).
- 예외는 없다.

함수 커버리지는 합격 기준이고, 아래 항목은 **통합 시험이 설계대로 충분한지 확인하는 완결성 기준**이다. 합격 기준을 채웠더라도 아래 항목이 비어 있으면 케이스를 추가한다.

- **인터페이스 커버리지**: 아키텍처에 정의된 모든 인터페이스(`ARCH-I-`)의 모든 동작(함수/메시지)이 시험에서 최소 한 번 호출된다.
- **오류 반환 커버리지**: 인터페이스에 정의된 모든 오류 반환값/경로가 시험된다.
- **시나리오 커버리지**: 아키텍처의 동적 거동(시퀀스)에 정의된 시나리오가 모두 시험된다.
- **요구사항 커버리지**: 통합 단계에 할당된 요구사항이 모두 시험에 연결된다.

100% 목표의 반복 절차는 단위 테스트의 6절과 같다. 미커버 함수는 (a) 의미 있는 케이스 추가, (b) 도달 불가·설계 결함으로 판정해 코드/설계를 수정, 중 하나로 처리하고 억지 케이스는 쓰지 않는다. 커버리지 예외는 없다.

## 3. 케이스 도출 (인터페이스 중심)

- **인터페이스 계약 시험**: 각 인터페이스의 사전조건·사후조건·반환값이 소비자-제공자 양쪽에서 맞는지 확인한다.
- **경계값/동치 클래스**: 인터페이스 인자의 범위 경계, 크기·길이 한계, 무효 입력.
- **PICT 조합**: 인터페이스 파라미터와 컴포넌트 상태/모드의 조합.
- **호출 순서/상태**: 허용 순서, 금지 순서(초기화 전 호출 등)에서의 거동.
- **오류 전파**: 하위 컴포넌트의 오류가 상위로 설계된 방식대로 전달·처리되는지.
- **자원/타이밍/동시성**: 아키텍처에 정의된 제약(소유권, 스레드 안전성, 시간 한계)이 있으면 이를 시험한다.
- **데이터 흐름 전 구간**: 한 입력이 여러 컴포넌트를 거쳐 최종 출력이 되는 대표 시나리오(end-to-end 일부).

## 4. Stub/Mock — 통합 수준 지침

- 통합 시험의 요점은 **실제 컴포넌트를 실제 인터페이스로 연결**하는 것이다. 시험 대상 컴포넌트들 사이를 Mock으로 끊지 않는다.
- Stub/Mock은 시험 범위 밖의 경계(하드웨어, OS, 외부 시스템, 시간)에만 쓴다.
- 통합 대상 인터페이스를 Mock으로 대체한 시험은 통합 시험으로 인정하지 않는다 (단위 시험에서 다룬다).

## 5. 테스트 주석 형식

단위 테스트와 같은 Doxygen 형식을 쓰고 추적 항목을 아키텍처 ID로 바꾼다.

```cpp
/**
 * @test      IT-ctrl_sensor-004
 * @brief     [목적] 센서 컴포넌트가 오류를 반환하면 제어 컴포넌트가 안전 상태로 전이한다.
 * @satisfies ARCH-I-007, ARCH-C-002, REQ-F-031
 * @technique 오류 전파 / 동치 클래스(무효 센서 값)
 * @input     센서 컴포넌트가 PROJ_ERR_RANGE를 반환하도록 하드웨어 경계를 설정
 * @procedure 1) 두 컴포넌트를 실제 인터페이스로 연결해 초기화한다.
 *            2) 제어 주기를 1회 실행한다.
 * @expected  제어 컴포넌트의 상태 == SAFE_STATE, 출력 명령 == 0
 *
 * @ai_model        claude-sonnet-5-5
 * @ai_date         2026-11-27
 * @requested_by    DongJoonHan
 * @human_reviewed  no
 * @reviewed_by     -
 * @reviewed_date   -
 */
TEST_F(CtrlSensorIntegrationTest, EntersSafeStateWhenSensorReportsRangeError)
```

시험 코드도 소스 코드이므로 Human-in-the-Loop 태그를 포함한다 (`CLAUDE.md` 2.4절). 통합 테스트는 `test/integration/`에 GoogleTest로 작성하고, TDD 테스트(`test/tdd/`)와 섞지 않는다.

## 6. 절차

1. 아키텍처에서 인터페이스·시나리오·통합 순서 도출 (통합 전략: 상향/하향/빅뱅 중 선택 이유 기록)
2. 통합 시험 명세 작성 (3절 기법)
3. 시험 코드 작성·실행
4. 커버리지/추적 확인, 미달 항목 반복 (2절)
5. 결함은 시험을 고치지 말고 결함으로 보고
6. `review` 스킬로 통합 테스트 체크리스트 리뷰
