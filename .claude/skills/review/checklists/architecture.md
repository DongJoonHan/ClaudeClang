# 아키텍처 리뷰 체크리스트 (SWE.2)

판정: OK / NG / N/A(사유) / 미확인

| ID | 점검 항목 | 판정 기준 |
|---|---|---|
| AR-01 | 모든 컴포넌트에 ID, 책임(한 문장), 할당 요구사항이 있다 | 누락 없음 |
| AR-02 | 모든 컴포넌트가 인터페이스를 정의한다 | 인터페이스 없는 컴포넌트 없음 |
| AR-03 | 인터페이스가 시그니처, 인자 범위/단위, 반환값, 사전/사후조건, 오류 처리를 포함한다 | 항목 누락 없음 |
| AR-04 | 인터페이스에 호출 순서, 스레드 안전성, 자원 소유권이 명시되어 있다 | 해당 사항 기술됨 |
| AR-05 | 컴포넌트 간 통신이 인터페이스로만 이루어진다 | 직접 접근(전역 공유, 내부 include, 구현 직접 참조) 없음 |
| AR-06 | 의존 관계에 순환이 없다 | 순환 의존 없음 |
| AR-07 | 의존이 구현이 아닌 인터페이스(추상)를 향한다 | 구체 구현 의존 없음 |
| AR-08 | 각 컴포넌트의 응집도가 높다 (책임이 한 문장으로 설명됨) | 다목적 컴포넌트 없음 |
| AR-09 | 결합도가 낮다 (데이터 결합 위주, 공통/제어/내용 결합 없음) | 높은 결합 사례 없음 |
| AR-10 | SOLID 원칙(S/O/L/I/D) 위반이 없다 | 위반 사례 없음 또는 사유 승인 |
| AR-11 | 모듈화·캡슐화: 내부 상태가 숨겨지고 공개 인터페이스만 노출된다 | 내부 노출 없음 |
| AR-12 | 동적 거동(주요 시나리오 시퀀스)이 기술되어 있다 | 시나리오 존재 |
| AR-13 | 동시성, 자원, 오류·복구 전략이 기술되어 있다 | 기술됨 |
| AR-14 | 품질 요구사항·제약사항이 설계 결정에 반영되고 근거가 기록되어 있다 | 요구-결정 연결 존재 |
| AR-15 | 설계 결정에 대안과 선택 이유가 있다 | 주요 결정에 기록 있음 |
| AR-16 | 요구사항 ↔ 컴포넌트/인터페이스 양방향 추적이 완전하다 | 미할당 요구사항, 근거 없는 컴포넌트 없음 |
| AR-17 | 통합 시험 대상 인터페이스와 시나리오를 식별할 수 있다 | 목록화 가능 |
