| ID | 점검 항목 | 판정 기준 |
|---|---|---|
| IT-01 | 통합 전략·순서·환경이 계획으로 문서화되어 있다 | 계획 존재, 전략 선택 이유 기록 |
| IT-02 | 시험이 아키텍처(인터페이스, 시나리오)에서 도출되었다 | 근거 ID 연결 |
| IT-03 | 모든 테스트 함수에 Doxygen 주석으로 목적, 입력값, 절차, 예상 출력값이 있다 | 항목 누락 없음 |
| IT-04 | 각 테스트에 추적 ID(`IT-`, 아키텍처/요구사항)와 적용 기법이 기록되어 있다 | 누락 없음 |
| IT-05 | 시험이 인터페이스 중심이다 (컴포넌트 간 연동 확인 위주) | 단위 시험의 재탕 아님 |
| IT-06 | 모든 인터페이스(`ARCH-I-`)의 모든 동작이 최소 한 번 시험된다 | 인터페이스 커버리지 100% |
| IT-07 | 인터페이스에 정의된 모든 오류 반환/전파 경로가 시험된다 | 누락 없음 |
| IT-08 | 아키텍처의 동적 거동 시나리오가 모두 시험된다 | 시나리오 커버리지 100% |
| IT-09 | 호출 순서·상태(허용/금지 순서) 시험이 있다 | 해당 시 확인 |
| IT-10 | 동시성·자원·타이밍 제약이 정의된 경우 시험된다 | 해당 시 확인 |
| IT-11 | 경계값 분석, 동치 클래스, PICT 조합이 적용되었다 | 적용 근거 존재 |
| IT-12 | **함수 커버리지 100%**를 LLVM(`llvm-cov`)으로 측정했고 **테스트 성공률이 100%**이다 (실패·건너뜀 없음, 예외 없음) | 함수 커버리지 100%, 성공률 100%, 도구 버전 기록 |
| IT-13 | 의미 없는 커버리지용 케이스가 없다 | 모든 케이스가 검증 목적과 단언을 가짐 |
| IT-14 | 시험 대상 컴포넌트 간 인터페이스가 Mock으로 끊어져 있지 않다 | 실제 컴포넌트 연결 |
| IT-15 | Stub/Mock이 시험 범위 밖의 경계에만 쓰였고 과도하지 않다 | 위반 없음 |
| IT-16 | 시험이 반복 가능하고 환경 의존이 문서화되어 있다 | 재실행 결과 동일 |
| IT-17 | 보고서에 결과, 커버리지, 미달/예외 사유, 도구 버전이 있다 | 기록 존재 |
| IT-18 | 아키텍처/요구사항 ↔ 통합 테스트 추적이 완전하다 | 시험 없는 인터페이스, 근거 없는 시험 없음 |
