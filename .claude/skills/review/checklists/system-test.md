# 시스템 테스트 리뷰 체크리스트 (SWE.6)

판정: OK / NG / N/A(사유) / 미확인

| ID | 점검 항목 | 판정 기준 |
|---|---|---|
| ST-01 | 시스템 테스트 케이스가 소프트웨어 요구사항(테스트 베이시스)에서 도출되었다 | 모든 케이스에 `REQ-` 연결 |
| ST-02 | **요구사항 커버리지 100%**: 모든 요구사항(`REQ-F/Q/L/C`, 안전 요구사항 포함)에 시험 케이스 또는 검증 방법이 있다 | 시험 없는 요구사항 0 |
| ST-03 | 케이스가 기능/비기능 시트(구분)로 나뉘어 있다 | 구분 있음 |
| ST-04 | 품질 요구사항(ISO 25010) 시험에 정량 기준과 측정 조건이 있다 | 합격 기준이 측정 가능 |
| ST-05 | 경계값 분석과 동치 분할이 적용되었다 | 적용 근거 존재 |
| ST-06 | 다중 입력 조합에 PICT 페어와이즈가 사용되었고 모델이 보관되어 있다 | 모델·제약·생성 결과 존재 |
| ST-07 | 각 케이스에 목적, 사전조건, 입력, 절차, 예상 결과가 있다 | 항목 누락 없음 |
| ST-08 | 기대값이 요구사항에서 도출되었다 (구현 출력을 베낀 것이 아니다) | 근거 확인 |
| ST-09 | 추적 매트릭스(요구사항 ↔ 시험 케이스)와 커버리지 요약이 일치한다 | 불일치 0 |
| ST-10 | 시험이 실제 통합된 시스템(실제 컴포넌트)에서 실행되었다 | Mock으로 대체된 시스템 경계 내부 없음 |
| ST-11 | 시험 결과(통과/실패/미실시)가 케이스별로 기록되어 있고 실패·건너뜀이 없다 | 시험 성공률 100% |
| ST-12 | 시험 환경, 도구 버전, 실행 일시가 기록되어 있다 | 기록 존재 |
| ST-13 | 결함이 발견되면 시험이 아니라 결함으로 보고·조치되었다 | 시험 수정으로 은폐한 흔적 없음 |
| ST-14 | 요구사항 ↔ 시스템 테스트 추적이 양방향으로 완전하다 | 고아 시험, 미시험 요구사항 0 |
