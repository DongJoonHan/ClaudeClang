# 리뷰 스킬 (A-SPICE SUP.2 관점)

공통 위치와 ID 규칙은 프로젝트 루트 `CLAUDE.md`를 따른다.

## 1. 필수 규칙

1. **모든 산출물은 이 스킬로 리뷰한다.** 리뷰 기록이 없는 산출물은 확정(baseline)된 것으로 보지 않는다.
2. **A-SPICE 요건에 따라 산출물별 체크리스트를 개발하고, 그 체크리스트를 근거로 리뷰한다.** 체크리스트 없이 인상으로 리뷰하지 않는다.

## 2. 산출물별 체크리스트

`checklists/` 폴더에 산출물 유형별 체크리스트가 있다. 리뷰 대상 유형에 맞는 파일을 사용한다.

| 산출물 | 체크리스트 | 관련 프로세스 |
|---|---|---|
| 요구사항 | `checklists/requirements.md` | SWE.1 |
| 아키텍처 | `checklists/architecture.md` | SWE.2 |
| 상세 설계 | `checklists/detailed-design.md` | SWE.3 |
| 소스 코드 | `checklists/code.md` | SWE.3 |
| 단위 테스트 | `checklists/unit-test.md` | SWE.4 |
| 통합 테스트 | `checklists/integration-test.md` | SWE.5 |
| 추적 매트릭스 | `checklists/traceability.md` | 전 단계 공통 |

체크리스트 관리 규칙:
- 항목마다 고유 ID(예: `RQ-03`)와 판정 기준(합격/불합격을 가를 수 있는 서술)이 있어야 한다.
- 프로젝트에서 새 위험·결함 유형이 발견되면 해당 체크리스트에 항목을 추가한다 (체크리스트는 살아있는 문서).
- 항목을 해당 없음(N/A)으로 처리하려면 사유를 쓴다.
- 체크리스트는 이 스킬이 제공하는 기본 초안이다. 조직의 A-SPICE 절차나 기존 체크리스트가 있으면 그것을 우선하고 이 파일을 갱신한다.

## 3. 리뷰 절차

1. **대상과 기준 확정**: 대상 산출물의 버전(커밋 해시), 입력이 된 상위 산출물, 적용 체크리스트와 그 버전.
2. **준비 확인**: 상위 산출물이 리뷰를 통과했는지 확인한다. 통과하지 않았다면 먼저 보고한다.
3. **항목별 점검**: 체크리스트 각 항목을 판정한다 — `OK` / `NG` / `N/A`. NG는 위치(파일:줄 또는 ID)와 근거를 쓴다. 판정은 실제 내용을 읽고 확인한 것에 한한다. 확인하지 못한 항목을 OK로 처리하지 않는다 (`미확인`으로 둔다).
4. **추적성 확인**: 대상 산출물의 상·하향 링크를 실제 `trace-matrix.md`와 대조한다.
5. **결함 분류**: 지적 사항마다 심각도(Major: 요구·안전·규칙 위반 / Minor: 품질·가독성 / Info: 제안)를 붙인다.
6. **결과 기록**: `docs/review/<산출물>-review-YYYYMMDD.md`에 아래 형식으로 남긴다.
7. **조치 확인**: NG와 Major/Minor 지적은 수정 후 재리뷰한다. 수정자가 임의로 "해결됨"으로 닫지 않는다. 재리뷰에서 해당 항목을 다시 점검한 뒤 닫는다.
8. **판정**: 통과 / 불통과 두 가지뿐이다. 통과는 체크리스트에 NG·미확인이 없고, Major·Minor 지적이 모두 재리뷰로 닫혔고, 추적성에 끊어진 링크가 없을 때만 가능하다. 부적합을 남긴 채 다음 단계로 넘어가는 "조건부 통과"는 없다 (Info는 기록만 하고 통과를 막지 않는다).

## 4. 리뷰 기록 형식

```
# 리뷰 기록: <산출물 이름>
- 대상: <파일/ID 범위>, 버전: <commit>
- 체크리스트: checklists/<파일>.md (<버전/날짜>)
- 리뷰 일자: YYYY-MM-DD
- 판정: 통과 | 불통과

## 체크리스트 결과
| 항목 ID | 판정 | 근거/위치 | 비고 |

## 지적 사항
| 번호 | 심각도 | 위치 | 내용 | 조치 | 상태(열림/재리뷰 후 닫힘) |

## 추적성 확인 결과
## 후속 조치
```

## 5. 리뷰어 에이전트

리뷰는 독립성을 위해 `reviewer` 서브에이전트(`.claude/agents/reviewer.md`)가 수행하는 것을 원칙으로 한다. 각 단계가 끝나면 호출하고, 통과 판정 전에는 다음 단계로 진행하지 않는다.

## 6. 리뷰어 태도

- 작성자가 아닌 관점으로 본다. 같은 세션에서 직접 작성한 산출물을 리뷰할 때는 체크리스트를 기계적으로 따르고, 가능하면 사용자나 별도 에이전트의 독립 리뷰를 권한다.
- 문제를 찾는 것이 목적이다. 통과시키기 위해 판정을 완화하지 않는다.
- 지적은 구체적으로: "무엇이, 어디서, 어느 기준에, 왜 문제인가".
